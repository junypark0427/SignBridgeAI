# SignBridge AI

한국수어(KSL)·미국수어(ASL)의 단어 동작을 수집·공유하고 브라우저에서 AI를 학습·시험하는 웹앱입니다. 손동작으로 구별 가능한 사전 선정 어휘가 대상이며 얼굴·입·머리·상체·문장 번역은 제외합니다.

## 구현 기능

- 메인: 학습시키기(Train AI), 직접 해보기(Try AI) 카드.
- 데이터 수집: 기존 웹캠·장치 선택·최대 두 손의 21개 관절·단어/의미 코드 등록·익명 촬영자/세션·카운트다운·시퀀스 녹화/재생/품질·IndexedDB·JSON 백업.
- 공용 데이터: 로컬 저장 후 Supabase 자동 업로드, 확인 완료/대기/실패, 재시도, 언어/표현 ID/촬영자/세션 필터, 페이지 조회, 전체 JSON, 로컬 병합.
- AI 모델 학습: TensorFlow.js 실제 단어 시퀀스 학습·중단, 클래스 선택·수량·유효성, 촬영자/세션 분할 검증, Epoch·Loss·Accuracy, 모델 저장/불러오기/파일 다운로드.
- 직접 해보기: 배포 모델 자동 로드 또는 브라우저 모델 선택, 단어 한 번 예측, 신뢰도·상위 후보, 입력된 한국어/영어 표기, 검증 표시와 출처가 있는 대응 표현. 체험 좌표는 저장·업로드하지 않습니다.

실제 수어로 학습·검증한 공개 모델은 아직 포함하지 않습니다. public/models/registry.json의 KSL/ASL은 null입니다. 모델이 없으면 결과를 만들지 않습니다. 합성 QA 정확도를 실제 수어 성능으로 해석하지 마세요. MediaPipe 손 검출 모델과 수어 분류 모델은 별개입니다.

## 실행

Node.js LTS 22.12 이상(검증 24.22.1), npm, 최신 Chrome/Edge를 권장합니다. 카메라는 localhost 또는 HTTPS에서 사용하며 index.html 직접 열기는 지원하지 않습니다.

```sh
npm ci
# .env.example을 .env.local로 복사하고 기존 Supabase 값을 입력
npm run dev
```

기본 주소는 http://127.0.0.1:5173/ 입니다. npm이 기본 경로에 없는 이 작업 환경에서는 `node .tools/package/bin/npm-cli.js run dev`를 사용할 수 있습니다. .tools는 Git 제외 작업 도구입니다.

```sh
npm test                 # 네트워크 없는 자동화 테스트
npm run build            # dist 생성
npm run preview          # 빌드 미리보기
npm run assets:prepare   # WASM 복사·공식 손 모델 해시 검사
npm run test:database    # 실제 DB에 is_test 합성 행 2개 INSERT 후 검증
```

설치 시 MediaPipe WASM을 public/wasm에 복사하고 공식 손 모델 SHA-256을 확인합니다. 카메라·학습·추론은 브라우저에서 실행합니다. Python/추론 서버, Auth/회원가입/관리자 코드, Netlify Functions는 추가하지 않습니다. TensorFlow.js는 모델 사용 시 지연 로드합니다.

## 수집과 공유

1. 학습시키기 → 데이터 수집에서 KSL/ASL을 선택합니다.
2. 검증된 사전·영상 자료에 따라 label, concept_id, 고유 sign_id, 설명·출처를 등록합니다. 변이마다 별도 ID를 사용하세요. 같은 의미 코드만으로 완전한 교차 대응이라고 간주하지 않습니다. 대응 검증 표시는 출처가 필요합니다.
3. 익명 촬영자·세션을 확인합니다. 실명/연락처를 넣지 않고 촬영자·환경이 바뀌면 새 세션을 만듭니다. 한 세션에는 한 촬영자만 허용합니다.
4. 카메라 시작 → 녹화 시작 → 기본 3초 카운트다운 → 단어 한 번 → 녹화 종료 및 검토. 자동 종료는 선택(초기 3초)이며 수동도 최대 120초/7200프레임입니다.
5. 좌표 재생·프레임 탐색·품질을 검토하고 저장합니다. 미감지는 hands:[]로 남기며 좌표를 만들지 않습니다. 절대 위치·방향·양손 상대 위치·원본 시간을 유지합니다.
6. IndexedDB 저장 후 전체 시퀀스를 Supabase 한 행으로 업로드합니다. 서버 응답/동일 UUID·내용 확인 후에만 완료입니다. 실패하면 로컬에 남고 재연결·앱 시작·수동 재시도로 복구합니다. 기존 로컬/JSON 병합 샘플도 업로드 대상입니다.

공개 데이터 정책: 로그인 없이 누구나 관절 데이터와 익명 ID를 읽고 샘플을 추가할 수 있습니다. Publishable Key와 RLS로 anon SELECT/INSERT만 허용하고 UPDATE/DELETE는 차단합니다. 익명 ID도 동작과 연결되므로 팀이 촬영 동의·공유 범위를 관리하세요. 실명·영상·기타 개인정보를 저장하지 않습니다. 사용자별 과다 추가/데이터 오염 차단은 없습니다.

브라우저 삭제는 이 기기 자료만 제거합니다. 이미 업로드했거나 전송 중인 공용 자료는 남습니다. 공용 수정·영구 삭제는 소유자가 Supabase Dashboard에서 수행합니다. 화면 이동은 카메라/초기화 자원을 종료하며 녹화 중에는 먼저 검토·저장 여부를 선택하게 합니다.

## 조회와 백업

하단 공용 데이터는 기본적으로 KSL·ASL 전체를 조회하며 언어/표현 ID/촬영자/세션으로 필터링할 수 있습니다. 촬영 언어와 공용 조회 언어는 서로 독립적입니다. 공용 전체 개수·필터 결과·마지막 조회 시각을 표시하고, 수집 화면 진입·탭 복귀·동기화 종료 시 다시 조회합니다. 실시간 구독은 사용하지 않으므로 그 외 변경은 새로고침으로 확인하세요. 목록은 메타데이터 페이지, 검토는 전체 프레임을 받습니다. 전체 JSON은 서버가 적은 행을 반환해도 마지막 ID에서 계속 조회하고 전후 총수가 바뀌면 다시 시도합니다.

### 다른 기기에서 데이터가 안 보일 때

1. 팀원 모두 같은 `https://signbridgeai1.netlify.app/` 주소를 사용하고 하단 버전을 확인합니다. 로컬 주소와 브라우저 프로필별 저장소는 다릅니다.
2. 단어 등록만으로는 공용 DB에 올라가지 않습니다. 녹화 → 검토 → 시퀀스 저장 후 카메라 아래와 목록의 **업로드 확인됨** 상태를 확인하세요. '이 기기에 저장됨'·대기·실패는 공유 완료가 아닙니다.
3. **이 기기의 수집 데이터**는 해당 브라우저 자료이므로 다른 사람이 올려도 0개일 수 있습니다. 옆 안내의 공용 개수와 **공용 목록으로 이동** 버튼을 사용하세요. 수집할 단어 목록도 로컬이며 공용 목록의 **이 페이지를 로컬로 가져오기**로 단어와 샘플을 함께 가져올 수 있습니다.
4. **팀 공용 데이터 → 필터 초기화 → 클라우드 새로고침**으로 전체를 확인합니다. 업로드가 성공한 자료는 이 목록에서 모든 팀원이 조회할 수 있습니다. 테스트용 `is_test=true` 자료는 제외합니다.
5. 실패하면 원본 기기의 JSON을 먼저 백업하고 업로드 재시도를 누릅니다. Netlify 페이지에 접속되어도 Supabase 통신은 학교망·기기 네트워크·브라우저 차단 설정 등의 영향을 따로 받을 수 있습니다. 오류 문구·발생 시각·샘플 ID를 확인해야 실제 원인을 구분할 수 있습니다. 확인 전에는 브라우저 데이터 삭제나 새 DB 생성을 하지 마세요.

기존 로컬 JSON 입출력도 유지합니다. 같은 ID·내용은 건너뛰고 다른 내용이면 전체 병합을 거절합니다. 비 UUID ID는 임의 변경하지 않으며 로컬에 남고 클라우드 업로드만 거절됩니다. IndexedDB는 주소·브라우저 프로필별로 별개라 localhost 자료는 Netlify로 자동 이전되지 않습니다. JSON으로 이동하세요. 브라우저 데이터 삭제·공간 회수·비공개 모드 종료로 유실될 수 있어 별도 백업이 필요합니다. 전체 검증/내보내기는 메모리를 쓰므로 큰 자료는 언어별로 관리하세요.

## 학습·체험

학습 화면에서 언어와 Supabase/로컬 자료를 선택하고 단어 2개 이상을 고릅니다. 각 단어 최소 학습 2개·독립 검증 1개가 필요하며 촬영자 분리를 우선하고 불가능하면 세션을 분리합니다. 같은 시퀀스의 프레임을 양쪽에 섞지 않습니다. 이 최소량은 정확도 보장 기준이 아닙니다.

미감지 >30%, <10프레임, <0.5초 자료는 학습에서 제외합니다. 한도는 유효 샘플 2000개·단어 100개, Epoch은 1~200입니다. 한국어/영어 표기는 검증한 값만 입력하세요. 중단하면 부분 모델을 저장하지 않습니다. 이 브라우저에 모델 저장 후 직접 해보기에서 시험할 수 있고 다른 컴퓨터에는 모델 파일 배포가 필요합니다.

직접 해보기는 모델·카메라 → 인식 시작 → 단어 한 번 → 인식 종료(최대 10초)입니다. 신뢰도와 1·2위 차이가 부족하면 확신 부족을 표시합니다. Softmax는 보정된 정확도가 아니며 미등록 동작도 오인식할 수 있습니다. 표기가 없으면 미등록, 검증 대응이 없으면 자료 없음으로 표시하며 임의 번역·영상을 생성하지 않습니다.

## 기존 Supabase·Netlify

기존 Supabase public.sign_samples를 사용합니다. [DB 설정](docs/DATABASE_SETUP.md), [SQL](supabase/migrations/202610240001_sign_samples.sql)을 참고하세요. 변수는 VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY이며 실제 값/.env.local은 Git 제외입니다. Secret/service_role은 앱에서 거절합니다.

기존 사이트는 [signbridgeai1.netlify.app](https://signbridgeai1.netlify.app/)입니다. 새 사이트를 만들지 않습니다. Project configuration → Environment variables에서 두 값을 Build에 제공하고 다시 빌드·배포해야 합니다. Vite 변수는 공개 JS에 반영됩니다.

| 항목 | 값 |
|---|---|
| 저장소 | junypark0427/SignBridgeAI |
| 기능 브랜치 | feature/data-collector |
| Build command | npm run build |
| Publish directory | dist |
| Node.js | 24 |

수동 배포는 환경 변수가 반영된 dist 폴더를 기존 프로젝트 Deploys에 올립니다. 소스 index.html 하나를 올리지 마세요. 계정 사용량 문제가 남으면 기존 계정에서 해결해야 합니다. 실제 확인 전에는 공개 사이트 업데이트 완료로 간주하지 않습니다.

모델 다운로드 → public/models 배치 → registry 변경 → 기능 브랜치 → 기존 사이트 재배포는 [모델 배포](docs/MODEL_DEPLOYMENT.md)를 참고하세요. 브라우저에서 GitHub로 자동 업로드하지 않습니다.

## 구조·협업

src/camera, mediapipe, collector는 기존 수집기를 유지합니다. database는 Supabase·동기화, ai는 학습·모델·예측, shared는 스키마·전처리, ui는 메인·수집·학습·체험입니다. public/models, supabase/migrations, tests, docs, netlify.toml, .env.example을 관리합니다.

main은 통합용이며 직접 Push·강제 병합하지 않습니다. 현재 feature/data-collector, 향후 feature/ksl·feature/asl을 사용하고 공통 전처리를 복제하지 않습니다. 실제 데이터·환경 변수·합성 QA 모델은 Git에 올리지 않고 검증한 공개 모델만 명시적으로 추가합니다.

상세 계약은 [MODEL_SPEC](docs/MODEL_SPEC.md), 실행 결과는 [VALIDATION](docs/VALIDATION.md)입니다. 다음 단계는 실제 어휘 수집, 미참여 촬영자 테스트, 미등록/신뢰도 보정과 언어별 모델 개선입니다. 문장 인식은 구간 분리·문법·맥락을 별도 모듈로 연구합니다.
