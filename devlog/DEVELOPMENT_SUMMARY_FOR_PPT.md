## 1. 프로젝트 배경과 목표

- **배경:** 한국수어와 미국수어를 배우고 소통할 때 두 언어의 표현을 연결하는 데 도움을 줄 수 있는 웹 도구를 목표로 했다. 특정 사용자 인터뷰나 사전 조사 결과는 Git 기록만으로 확인되지 않는다.
- **초기 목표:** 웹캠에서 수어 단어 하나의 손동작을 시간순으로 수집하고, KSL·ASL별 학습 자료를 만들며, 공통 의미 코드를 이용해 등록된 다른 언어의 이름을 찾아본다. 시작 단계는 완전한 문장 번역이 아닌 단어 단위다.
- **핵심 질문:** 적은 예시로도 팀이 공용 데이터를 모으고, 사용자가 자신의 손동작과 등록된 동작을 바로 비교해 볼 수 있을까?

## 3. 핵심 AI 흐름을 쉽게 설명하기

**카메라 → 관절 좌표 → 동작 시퀀스 → 정규화·트림 → DTW 비교 → 단어 후보 → 공통 의미 코드 → 등록된 반대 언어 이름**

1. **MediaPipe:** 손가락과 손목의 위치를 손당 21개 점으로 나타낸다. 이는 수어 단어 자체를 알아내는 결과가 아니라 이후 비교에 쓰는 입력이다.
2. **시퀀스:** 한 장의 사진이 아니라 여러 순간의 좌표와 시간으로 손이 움직인 순서를 저장한다. 손이 보이지 않은 순간은 누락으로 남긴다.
3. **전처리:** 카메라 앞 손 크기가 달라져도 비교할 수 있도록 손목을 기준으로 상대 좌표를 계산한다. 손의 원래 위치와 양손 사이 거리도 별도로 남긴다.
4. **DTW:** 두 사람이 같은 동작을 다른 속도로 수행할 수 있으므로, 시간 흐름을 맞춰 가며 등록 예시와 입력의 차이를 계산한다. 가까운 예시가 있는 단어를 후보로 보여 준다.
5. **의미 연결:** 같은 `concept_id`로 등록된 KSL·ASL 이름을 조회한다. 같은 코드가 완전한 수어 대응을 증명하는 것은 아니다.
6. **구절 실험:** KSL 단어의 의미 범주와 서술어가 요구하는 성분을 정해 놓고, 지원하는 조합에만 조사를 붙인다. 예: `사랑 + 배우다 → 사랑을 배우다`.

발표에서는 **“기본 Try AI는 DTW 기반 예시 비교”**라고 표현한다. TensorFlow.js 학습 코드는 고급 실험에 존재하지만, 기본 Try AI가 실제 학습된 신경망을 사용한다고 설명하면 안 된다. 합성 데이터 학습 시험이 곧 실제 수어 데이터로 학습한 모델의 정확도 증명은 아니다. [비교 규격](../docs/COMPARISON_SPEC.md), [모델 배포 규격](../docs/MODEL_DEPLOYMENT.md)

## 4. 기술적 문제와 해결 사례

| 문제 | 확인된 해결 과정 | 발표할 때의 한계 |
| --- | --- | --- |
| 로컬 자료가 0개일 때 팀 자료가 보이지 않는 것처럼 혼동 | 로컬·업로드 대기·서버 확인과 공용 목록의 의미를 UI에 구분 | 팀원 기기에서 겪은 모든 증상의 유일한 원인으로 확인된 것은 아님 |
| 손을 올리기 전후의 미검출 프레임이 품질 평가를 흐림 | 첫·마지막 유효 검출 사이를 학습·비교용 사본으로 트림하고 원본을 보존 | 동작 중 긴 누락은 복원하지 않으며 경고·재촬영이 필요할 수 있음 |
| 학습 데이터가 소량이라 신경망 학습이 어려움 | 예시 1개부터 시험할 수 있는 DTW 최근접 비교 도입 | 표본이 적어도 실행된다는 뜻이지 실제 인식 정확도를 보장하지 않음 |
| 큰 시퀀스 조회가 느리고 시간 초과 가능 | 가벼운 목록을 먼저 조회하고 최대 3개씩 원본을 불러오도록 변경 | 당시 41개 약 18→12초는 특정 환경의 기록이며 일반 성능 수치가 아님 |
| 연속 동작을 하나의 단어로 처리 | 문장 모드에서 손 미검출 기본 600ms를 이용해 구간 분리 | 합성 좌표 시험 통과. 실제 두 수어 연속 수행은 해당 기록상 미검증 |
| 음성 출력의 기기 차이 | 언어별 듣기·중지와 브라우저 미지원/오류 안내를 코드에 구현 | 모의 음성 API 테스트와 실제 스피커에서의 청취 검증은 다름 |

수집·조회 도중 탭을 벗어나거나, 공용 자료를 삭제·수정할 때 발생할 수 있는 상태 문제도 별도 코드와 테스트로 다뤘다. 구체적인 커밋과 증거는 [상세 개발 로그](DEVELOPMENT_LOG.md)를 참고한다.

## 5. 현재 기능과 제한

**기본 브랜치에 구현된 기능**

- 웹캠 손 관절 추출 및 단어 시퀀스 수집, 검토·품질 경고.
- KSL·ASL 자료의 브라우저 임시 저장, Supabase 공용 저장·조회·수정·삭제, JSON 백업.
- 공용 예시를 쓰는 DTW 단어 비교와 상위 후보·불확실 표시.
- 같은 의미 코드의 등록 이름 표시, 한국어·영어 듣기.
- 손 내림 기반 단어 분리와 제한된 KSL 한국어 구절 생성 Beta.

**한계와 다음 단계**

- 더 많은 촬영자·배경과 촬영 세션을 수집하고 학습에 참여하지 않은 사람으로 평가해야 한다.
- 얼굴 표정, 입, 머리와 상체를 현재 입력으로 사용하지 않는다. 손만으로 구별하기 어려운 표현이 있다.
- 자동 분리는 손을 의도적으로 화면에서 내리는 방식이다. 자연스러운 연속 수어의 모든 경계를 구분하지 못한다.
- KSL과 ASL은 각각 독립된 언어이며 공통 의미 코드나 한국어 단어 나열만으로 완전한 수어 번역을 주장할 수 없다.
- 공용 데이터는 로그인 없이 허용된 변경·삭제가 가능하다. 실제 영상·실명은 저장하지 않고 JSON으로 백업해야 한다.
- `design`, `Cross-translate`의 별도 커밋은 기본 브랜치에 병합된 것으로 확인되지 않았다. 현재 공개 원격에는 `main` 브랜치가 조회되지 않는다.

## 6. 발표에 사용하기 좋은 실제 화면

1. **메인 화면:** 학습시키기와 Try AI 메뉴. 프로젝트의 사용 흐름을 소개.
2. **데이터 수집:** KSL/ASL 선택, 웹캠과 손 관절 표시. 손 좌표가 시퀀스로 수집되는 과정을 설명.
3. **팀 공용 데이터:** 단어별 그룹과 시퀀스 수, 검토 화면. 실제 촬영자·세션 ID나 팀원 이름이 보인다면 가리거나 테스트용 자료로 대체.
4. **Try AI 결과:** 입력 언어, 등록 이름 두 가지, 상위 후보와 점수, 듣기 버튼. 점수를 정확도·확률처럼 설명하지 않기.
5. **문장 인식 Beta:** 손 미검출 간격, 누적된 `사랑 → 배우다`, 구절 변환 결과. 실제 동작을 직접 촬영한 검증인지 합성 테스트인지 명시.

위는 화면 제안이며 이 문서가 실제 화면 캡처나 실연 성공을 보증하지 않는다. 시연 전 카메라 권한, 네트워크, 공용 데이터, 음성 출력과 브라우저 상태를 확인한다.

## 7. 발표에서 말할 수 있는 성과와 검증

- 한 손 모양을 한 번 찍는 방식에서 나아가 **시간 정보가 있는 동작 시퀀스를 수집·공유·비교하는 전체 흐름**을 구성했다.
- 데이터가 적을 때의 제약을 발견하고, 별도 수동 학습을 요구하지 않는 DTW 비교 경로를 구현했다.
- 누락 프레임과 언어별 데이터, 공용 동기화·변경 권한을 고려한 관리 기능을 만들었다.
- 실제 수어 번역이라고 과장하지 않는 범위에서, 단어 결과를 규칙 기반 한국어 구절 및 음성 출력으로 연결했다.
- 문서 작성 시점에 현재 코드 자동화 테스트 **98개와 빌드가 통과**했다. 당시 기록의 실카메라·합성 데이터 시험은 [상세 로그](DEVELOPMENT_LOG.md)에 구분되어 있다. 테스트 통과를 실제 사용자 대상 정확도라고 발표하지 않는다.
