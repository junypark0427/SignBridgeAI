# 공용 샘플 메타데이터 수정 설계 초안

공용 메타데이터 수정 기능의 구현 시 고려한 설계 기록이다.

## 보존해야 할 규칙

- `sign_samples`의 `label`, `sign_id`, `concept_id`는 `sign_metadata` 내부에도 존재한다. 두 곳을 함께 변경해야 기존 변환 및 단어 목록이 일관된다.
- 동일한 표현 ID를 공유하는 샘플의 `sign_metadata`가 다르면 `signCatalog`와 JSON 내보내기가 오류를 낸다. 개별 샘플의 표현 정보 변경도 다른 샘플과 충돌하는지 확인해야 한다.
- `frames`, 시간 정보, 언어와 샘플 UUID는 수정하지 않는다. 촬영자와 세션 ID는 샘플별로 변경할 수 있다.
- 편집 당시와 저장 당시 데이터가 달라졌다면 덮어쓰지 말고 새로 조회해 다시 확인한다.
- 로컬 사본이 클라우드보다 오래된 경우를 구분하고 재업로드로 클라우드 메타데이터가 되돌아가지 않도록 한다.

## 구현과 검증 사항

1. DB에서 허용할 열을 한정하고 원본 좌표 변경을 차단한다. 일괄 변경은 확인한 UUID와 이전 값을 기준으로 원자적으로 적용한다.
2. 동일 표현 ID의 충돌 및 기존 데이터의 의미를 확인하고, 충돌하는 개별 수정은 거부하거나 새 표현 ID를 요구한다.
3. 변경 전후, 대상 개수 및 실제 대상을 보여주고 명시적으로 확인한다.
4. 성공 후 목록, Try AI, 문장 변환, 로컬 캐시 및 내보내기를 검증한다. 서로 다른 기기의 오래된 캐시도 고려한다.
5. 테스트 전용 샘플로만 실제 UPDATE, 동시 수정, 부분 실패, 프레임 보존 및 권한 제한을 확인한다.

로그인 없이 UPDATE를 허용하면 사이트 이용자 누구나 허용된 메타데이터를 변경할 수 있다. 권한 변경을 적용하기 전에 이 한계와 JSON 백업 방법을 안내해야 한다.
